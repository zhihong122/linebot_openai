# Medication-bag V2

The V2 online path checks verified English names or aliases, strength, manufacturer, and Chinese name in that order. A unique full match and an independently verified leaflet link for the current version are required. Partial candidates never supplement. The original mode retains its old matcher. After a unique match, it fills only missing clinical fields from an active, manually reviewed summary for the current leaflet. It never calls the online summary model in V2. The separate consultation path retains full-leaflet RAG.

1. Apply `RAG/sql/v2_precomputed.sql` to a test copy of the RAG database with `psql -v ON_ERROR_STOP=1 -f RAG/sql/v2_precomputed.sql`. Then apply `RAG/sql/v2_identity.sql` and populate verified identity data from source records. The migrations expect the existing `public.rag_drugs` and `public.rag_chunks` tables. Deploy the application with its V2 switch off while preparing data.
2. In the environment with the configured RAG database and gpt-oss endpoint, run `python -m RAG.rag.summary_jobs generate DRUG_ID`. The command produces one inactive draft for the current leaflet version.
3. A qualified reviewer must inspect the corresponding `rag_v2.drug_summaries` row, compare its evidence with the full source, verify the product identity and coverage of major precautions, and record reviewer approval only after these checks. Run `python -m RAG.rag.summary_jobs activate DRUG_ID LEAFLET_VERSION --reviewed-by REVIEWER --confirm-reviewed`. Use optional `--review-ms` for measured review duration in milliseconds.
4. Set `RAG_MEDICATION_PRECOMPUTED=true` in the application environment after validated summaries are ready. With the switch off, the existing real-time flow remains active and its measurements retain the `legacy` label. With the switch on, measurements use `V2`. A missing, inactive, or stale summary yields a clear no-supplement result.

Use the same masked image, model settings, and leaflet content when measuring the two paths. Confirm successful supplementation and source identity before comparing RAG latency. Review coverage and failure rates separately. If leaflet content changes, the previous summary is immediately ineligible and the replacement must be generated and reviewed.
